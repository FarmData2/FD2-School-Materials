## Homework 04 - Inputs and User Events

### Binding `<input>` values with `v-model`

- The `v-model` directive binds the value of an HTML `input` element to a property in the Vue `data`.
  - If the `input` element is changed by the user, the value in the `data` property changes.
  - If the `data` property is changed by code, the value displayed in the `input` element also changes.
- Show the `harvest-date` `input` in the code:
  - In the `input` we have `v-model="date"`
    - So the value of the `input` is bound to the `date` property in the `data`.
  - In the `data` we added `date: '2019-06-15'`
    - This sets the initial value of the `date` `input` to June 15, 2019.
- Demo the binding with the Vue Devtools.
  - Show the initial value of `date` in the tools and the `input`.
  - Change the date in the `input`.
    - Point out the change in the `data`.
    - Note: May need to use the "refresh" button if the `date` doesn't update immediately in the `data`.
  - Change the date in the `data`.
    - Point out the change in the `input`.
- The other inputs are similar:
  - Each input uses `v-model` to bind its value into a `data` property.
    - "Crop" `input` is bound to `crop`.
    - "Quantity" `input` is bound to `quantity`.
    - "Unit" `input` is bound to `unit`.
    - "Comment box" `input` is bound to `comment`.

### Binding the Radio Buttons

- The radio `input`s are a little different...
- Show the behavior in the Vue Devtools
  - Clicking a radio button sets the value of the `pickedPlant` property in the `data` to the `id` of the associated plant in the `plantList`.
- How does this work?
  - Recall that the `plantList` is an array of object describing the plants in the table.
    - Each plant has an `id` property, as well as the other properties (`date`, `location`, `bed`).
  - The table on the page is generated by a `v-for` on the `<tr>` element of the `table`.
    - Each row of the table contains:
      - An `input` of type `radio`.
      - The `location`, `bed` and `date` from the `plant`. 
  - Look at the `radio` `input` more closely:
    - The `name` is the same for all of the radio buttons.
      - Radio buttons with the same `name` are _grouped_, which ensures that only one button in the group can be selected at a time.
    - The radio button is bound (`v-model`) to the `pickedPlant` property in the Vue `data`.
    - The `value` of each radio button is set to the `id` of the associated object in the `plantList` by binding it to `plant.id`.
      - `v-bind="plant.id"`
      - We can see this in the Devtools
        - Use the "Picker" tool (to the left of "Inspector" at the top of the Devtools - or `Ctrl+Shift+C`) to point at the first radio button.
          - This reveals the HTML code for that element.
          - Notice that the `value` attribute of the `input` is `1`.
        - Point a the second, third, fourth radio buttons.
          - The `value` of each one is the `id` of the corresponding plant from the `plantList`.
    - Lastly, we use `v-model` so that when a radio button is clicked, its `value` will be placed into the `pickedPlant` property.
      - `v-model="pickedPlant"`
      - Note that every radio button has the same `v-model`. So, when any of the radio buttons is clicked, it takes its own `value` and puts it into the `pickedPlant` property.
        - If the third button is clicked, it uses its `value` (`3`).
        - But if the second button is clicked it uses its `value` (`2`).
          - Note that the correspondence between the position of the button and the `value` here is coincidental.  If you'd like to confirm this, re-arrange the objects in the `plantList` without changing their `id`s.

## Tutorial 05 - Methods and Conditional Rendering

### Conditional Rendering (`v-if`)

- Demo:
  - Load the `05-Vue3-Tutorials-Soln/index.html` page.
  - Notice two things:
    - The shopping list doesn't appear.
      - Because it is empty...
        - Instead we see the "Nice job!" message.
      - The form for adding an item doesn't appear.
        - Because we changed the code to only show it when the "Add Item" button is clicked.
  - What did we use to do that?
    - Vue's `v-if` and `v-else` directives.
    - Look at the code:
      - Consider the "Nice job!" message.
        - This message only appears if the list is empty.
        - `v-if="items.length === 0"`
        - What would happen if we use `2` instead of `0` here? 
        - What about if we use `<= 3` instead of `=== 0`?
      - Consider the form elements for adding a new item.
        - They only appear when `editing` is `true`.
          - `<div v-if="editing" ...>`
            - Same as: `v-if="editing==true"`
            - The `<div>` was added and it surrounds all of the form elements.
              - If the `<div>` is hidden, all of its contents are hidden.
              - This is preferable to adding a `v-if` to each of the individual elements.
                - It is a common technique that is used in web apps (with Vue and other frameworks).
          - What is `editing`? 
            - It is a property that you added to the Vue `data`.
          - Demo with the Vue Dev tools:
            - Toggle the `editing` property using the check box.
              - `false` -> form is hidden.
              - `true` -> form is shown.
      - Consider the buttons for "Add Item" and "Cancel".
        - Demo that one or the other is shown.
        - In the code:
          - "Cancel"
            - `v-if="editing"`
          - "Add Item"
            - `v-else`
        - Both buttons call the `doEdit` method and pass a boolean value.
          - The `doEdit` method uses its parameter to set the `editing` property.
          - Clicking "Cancel" passes `false` to `doEdit` which causes `editing` to be set to `false`, which in turn causes the "Add Item" button to appear and the "Cancel" button to be hidden.
          - Conversely, clicking "Add Item" passes `true` to `doEdit` which causes `editing` to be set to `true`, which in turn causes the "Cancel" button to appear and the "Add Item" button to be hidden.
          - Pretty clever!

### Methods

- The tutorial added a `methods` property to the Vue instance:
  ```
  ...
  data() {
    ...
  },
  methods: {
    ...
  },
  ...
  ```
  This `methods` property can contain methods (a.k.a. functions) that can be called from other places in the page.
- You added the `saveItem` method:
  ```
  ...
  methods: {
    saveItem() {
      this.items.push({ id: this.items.length + 1, label: this.newItem });
      this.newItem = '';
    }
  },
  ...
  ```
  - This method contains the code for adding the new item to the `items` array.
    - Notice that we need to use `this.` ("this dot") to access properties in the Vue instance when writing code in the `methods` section.
      - This is different than when we write code directly in the `<template>`.
        - For example, we don't use `this.` in `v-on` or `v-model` or `v-bind` statements, or in `{{ }}` in the `<template>`.
        - But anytime we want to access Vue instance properties in the `<script>` we need to use `this.`
          - `this.items.push(...)`
          - `this.newItem`
          - etc.
- Once you have a method, you can call it from the `<template>` or from other places in the `<script>` (e.g. from other methods).
  - The "New Item" input and the "Save" button now both call the `saveItem` method instead of repeating the code.
  - This makes maintenance of the code easier.
    - For example, when the tutorial added code to the `saveItem` method to clear the input after the new item was saved.
      - Because the code was factored out into a method the new code only needed to be added at one place instead of two.


## Extra Tips

- When writing code in the Vue instance (e.g. a method), you are going to forget `this.`, when you do just remember that you need `this`.
  - Code in the `<script>` must use `this.` to access data and methods.
  - Code in the `<template>` cannot use `this.` to access data and methods.

- A lot of what you know about other languages will transfer...
  - JavaScript comparison operators are similar to Java/Python/C
    - `==`, `>`, `<`, `>=`, `<=`, `!=`
    - Note: JavaScript also has `===`
      - `==` compares values with _type coercion_.
        - `3 == "3"` 
          - Will be `true` because "3" can be "coerced" into 3 by parsing it as an integer.
          - JavaScript will try to coerce values when using `==`. 
          - If a coercion makes them equal then the result is `true`.
          - Only if no coercion works will the value be `false`. 
      - `===` compares values and their types.
        - `3 === "3"`
          - Will be `false` because 3 is an integer and "3" is a string.
          - No coercion is done when `===` is used.
      - Most often `==` is suitable, but `===` can be used if you are concerned about both the type and the value.
